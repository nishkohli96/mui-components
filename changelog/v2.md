# Changelog - v2

## [2.0.0](https://github.com/nishkohli96/mui-components/tree/v2.0.0)

**Released - 6 August, 2026**

### ⚙️ Project & Tooling
- Upgraded `pnpm` from `11.10.0` to `11.20.0`.
- Added links to the corresponding StackBlitz playground for each `v1` component.

### 💥 Breaking Changes
- Upgraded to **Material UI v9** and **MUI X Date Pickers v9**. `peerDependencies` are now `^9.0.0` for `@mui/material`, `@mui/system`, `@mui/icons-material` and `@mui/x-date-pickers` — the built output calls `v9`-only APIs, so MUI `v6`/`v7` are no longer supported.

  No prop on any `MUI*` component was renamed or removed, but props forwarded *through* them into MUI (`textFieldProps`, `checkboxProps`, `slotProps.textField`) follow MUI's new slot shapes.
- Preserved floating-label shrink behaviour on every Autocomplete. In `v7` the label props reached the `TextField` implicitly through the params rest-spread; in `v9` they moved inside `slotProps.inputLabel`, so the rest-spread silently stopped delivering them and labels overlapped the selected value.
- Preserved picker accessibility attributes (`aria-labelledby`, `aria-describedby`, `aria-invalid`, `aria-required`), which would otherwise have been dropped silently since `v9` ignores the old `inputProps` on picker text fields.
- Docs: replaced the `*Outline` icons removed in `v9` with their `*Outlined` counterparts.
- Docs: reworked the dark-mode `MuiAlert` theme override for `v9`, which collapsed the per-severity `standard{Info,Success,Warning,Error}` style-override slots into a single `standard` slot driven by `ownerState.severity`.

### ✨ Enhancements
- Migrated the Autocomplete family (`MUIAutocomplete`, `MUIAutocompleteObject`, `MUIMultiAutocomplete`, `MUIMultiAutocompleteObject`, `MUICountrySelect`) to v9's reshaped `AutocompleteRenderInputParams`, where `InputProps`/`inputProps` were collapsed into `slotProps.{input,htmlInput,inputLabel}`.
- Migrated all nine date/time pickers from the removed `slotProps.textField.inputProps` to `slotProps.textField.slotProps.htmlInput`.
- Migrated `MUIPhoneInput`'s country menu from the removed `MenuProps.PaperProps`/`MenuProps.MenuListProps` to `MenuProps.slotProps.paper`/`MenuProps.slotProps.list`.
- Replaced removed MUI system props (`marginRight`, `color`, `textAlign`, `alignItems`, etc.) with their `sx` equivalents.
- Exposed previously-unreachable internal sub-component props:
  - `MUIPasswordInput`: `iconButtonProps` for the show/hide toggle button.
  - `MUISelect`: `menuItemProps` (every option `MenuItem`) and `inputLabelProps` (the inline `InputLabel`).
  - `MUIAutocomplete`, `MUIAutocompleteObject`, `MUIMultiAutocomplete`, `MUIMultiAutocompleteObject`: `circularProgressProps` for the loading spinner.
  - `MUIPhoneInput`: `countrySelectProps` for the flag/dial-code trigger `Select`, and `searchCountryProps.menuItemProps` for every country `MenuItem`.
- Reorganized component props in the props table based on their relevance.
- Updated form examples with newly added props

### 🐞 Bug Fixes
- `MUINumberInput`: Set `slotProps.htmlInput.step` to `any` (except for `onlyIntegers`) for decimal inputs (was reusing `resolvedStepAmount`), preventing false "stepMismatch" validation errors on values like 23.45.
- Docs: Correct return value of `MUICountrySelect` in the **Usage Section**.
- Docs: Corrected the `value prop` description for `RHFCheckboxGroup` by removing `null`.
- Docs: Set **Paper** `elevation` to `0` for `Drawer` for consistent appearance, esp in dark mode.
