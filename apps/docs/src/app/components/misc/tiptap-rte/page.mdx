# MUITipTapRte

<AvailabilityBanner componentName="MUITipTapRte" version="2.2" />

`MUITipTapRte` wraps [Tiptap](https://tiptap.dev/)'s headless `useEditor` hook,
backed by an **HTML string** value — a lighter, dependency-thinner alternative
to [MUIRichTextEditor](/components/misc/rich-text-editor) (CKEditor 5). Since
Tiptap ships no UI of its own, this component includes a hand-built formatting
toolbar (bold, italic, underline, strikethrough, headings, lists, blockquote,
code block, links, alignment, undo/redo) driven entirely by the editor's own
extensions.

## Usage

```tsx
import MUITipTapRte, {
  DefaultEditorExtensions,
  type MUITipTapRteProps
} from '@nish1896/mui-components/misc/tiptap-rte';
```

The value of `bio` will be an **HTML string**.

```tsx
const [bio, setBio] = useState('');

<MUITipTapRte
  fieldName="bio"
  value={bio}
  onValueChange={({ newValue }) => setBio(newValue)}
  placeholder="Tell us about yourself"
/>
```

### Choosing the formatting options

Pass a custom `editorExtensions` array, or extend `DefaultEditorExtensions`,
to control what the editor supports. Every toolbar button checks whether its
backing extension is loaded before rendering. A custom set missing e.g.
`Heading` or `TextAlign` simply omits those buttons instead of throwing an
error when clicked.

```tsx
import MUITipTapRte, { DefaultEditorExtensions } from '@nish1896/mui-components/misc/tiptap-rte';
import Table from '@tiptap/extension-table';

<MUITipTapRte
  fieldName="bio"
  value={bio}
  onValueChange={({ newValue }) => setBio(newValue)}
  editorExtensions={[...DefaultEditorExtensions, Table]}
/>
```

### Configuring the editor

Use `editorOptions` to reach into `useEditor` for anything not exposed as its
own prop. Pass `onCreate`, `onFocus`, `onUpdate` or `onBlur` here and they
reach `useEditor` unmodified.

```tsx
<MUITipTapRte
  fieldName="bio"
  value={bio}
  onValueChange={({ newValue }) => setBio(newValue)}
  editorOptions={{
    autofocus: true,
    onCreate: ({ editor }) => console.log('ready', editor),
    onFocus: ({ editor }) => console.log('focused', editor),
    onBlur: ({ editor }) => console.log('blurred', editor),
    onUpdate: ({ editor }) => console.log('newContent', editor.getHTML()),
    editorProps: { attributes: { spellcheck: 'false' } }
  }}
/>
```

- `onUpdate` is never replaced, only chained. It first calls `onValueChange`
  with the editor's latest HTML, then your `editorOptions.onUpdate`, so `value`
  is always in sync by the time your own handler runs.
- `editorOptions` is layered *underneath* this component's own required wiring
  (`content`, `editable` and the accessibility attributes), so it can't break
  the controlled-value contract.
- `editorProps.attributes` is deep-merged rather than replaced.

### Styling the editor

`containerProps` styles the outer bordered box, and `contentContainerProps`
styles the scrollable box directly wrapping the editor content. Both merge
their `sx` with this component's own base styles rather than replacing them.

```tsx
<MUITipTapRte
  fieldName="bio"
  value={bio}
  onValueChange={({ newValue }) => setBio(newValue)}
  containerProps={{ sx: { borderColor: 'primary.main' } }}
  contentContainerProps={{ sx: { minHeight: 240 } }}
/>
```

### Custom toolbar

`renderToolbar` replaces the built-in toolbar entirely. Pass `() => null` to
hide it. It receives the live `editor` instance and the field's resolved
`disabled` state, so a custom toolbar can drive the same
`editor.chain()...run()` commands and respect the same disabled state.

```tsx
<MUITipTapRte
  fieldName="bio"
  value={bio}
  onValueChange={({ newValue }) => setBio(newValue)}
  renderToolbar={(editor, disabled) => (
    <Button
      disabled={disabled}
      onClick={() => editor.chain().focus().toggleBold().run()}
    >
      Bold
    </Button>
  )}
/>
```

## API

Pass a custom `editorExtensions` to control the Tiptap extension set (and, in
turn, which toolbar buttons render). Props marked with <strong
style={{ color: 'var(--mui-palette-error-main)' }}>{'*'}</strong> are required.
