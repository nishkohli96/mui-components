# MUIUnitInput

<AvailabilityBanner componentName="MUIUnitInput" version="1.3" />

`MUIUnitInput` pairs a numeric quantity ([MUINumberInput](/components/mui/number-input))
with a unit picker ([MUISelect](/components/mui/select)) - currency, weight, temperature,
or any other unit set - rendered borderless inside one bordered pill, similar in spirit to
[MUIPhoneInput](/components/mui/phone-input)'s country + number pairing.

`fieldName` and `customIds` take one entry per control (`quantity`/`unit`) so
each is registered independently against a flat form schema, but `value` /
`onValueChange` still report the pair together as one `{ quantity, unit }`
object.

`unitOptions` accepts either a plain string array (or a string-literal
union/enum's values, for literal-union safety), or an object array read via
`labelKey`/`valueKey` — the same convention as `MUISelect`. The type of
`value.unit`/`newValue.unit` is computed the same way `MUISelect` computes
its own value type, from `unitOptions`/`valueKey` — there's no separate
`Unit` type argument to pass.

With a plain string array, this infers on its own from `unitOptions`. With
an object array, TypeScript can only infer the option shape from `unitOptions`
itself — if `value` also comes from a `useState` you've already typed with a
concrete union (e.g. `useState<MUIUnitInputValue<Currency>>(...)`), pin the
option type explicitly on the JSX tag (`<MUIUnitInput<CurrencyOption, 'label', 'code'>>`)
so the two don't fight each other during inference.

## Usage

```tsx
import MUIUnitInput, { MUIUnitInputValue } from '@nish1896/mui-components/mui/unit-input';
```

Plain string `unitOptions`:

```tsx
const [price, setPrice] = useState<MUIUnitInputValue>({ quantity: null, unit: 'USD' });

<MUIUnitInput
  fieldName={{ quantity: 'priceAmount', unit: 'priceUnit' }}
  value={price}
  onValueChange={({ newValue }) => setPrice(newValue)}
  unitOptions={['USD', 'EUR', 'GBP']}
  nonNegative
  maxDecimalPlaces={2}
/>
```

Object `unitOptions` via `labelKey`/`valueKey` — `newValue.unit` is typed
`'USD' | 'EUR' | 'GBP'`. Since `price` is a `useState<MUIUnitInputValue<Currency>>`
already typed with that union, the option shape (`CurrencyOption`) is pinned
explicitly on the tag so it isn't inferred inconsistently from both `value`
and `unitOptions` at once:

```tsx
type Currency = 'USD' | 'EUR' | 'GBP';
type CurrencyOption = { code: Currency; label: string };

const currencyOptions: CurrencyOption[] = [
  { code: 'USD', label: 'US Dollar' },
  { code: 'EUR', label: 'Euro' },
  { code: 'GBP', label: 'British Pound' }
];

<MUIUnitInput<CurrencyOption, 'label', 'code'>
  fieldName={{ quantity: 'priceAmount', unit: 'priceUnit' }}
  value={price}
  onValueChange={({ newValue }) => setPrice(newValue)}
  unitOptions={currencyOptions}
  labelKey="label"
  valueKey="code"
  unitPosition="start"
/>
```
