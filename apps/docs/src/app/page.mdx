# @nish1896/mui-components

**A suite of 25+ production-ready [Material UI](https://mui.com/material-ui/) form
components — fully typed, tree-shakable, and independent of any form library.**

Every component wires up the pieces you rebuild on every project — label placement,
error state, helper text, accessibility attributes and stable element IDs — while
staying a plain controlled component: pass a `value`, receive changes through
`onValueChange`, and keep validation wherever you like. Use it with `useState`,
[React Hook Form](https://react-hook-form.com/),
[TanStack Form](https://tanstack.com/form/latest),
[Formik](https://formik.org/), or your own state management.

Head over to [Getting Started](/getting-started) for installation, the package
structure and a quick start.

<Callout severity="info">
  For building forms with **React Hook Form**, we recommend using
  [@nish1896/rhf-mui-components](https://rhf-mui-components.vercel.app/). It
  offers a similar API to this package but is designed specifically for
  seamless integration with React Hook Form.
</Callout>

## Why this package?

- **No form-library lock-in** — components speak `value` / `onValueChange` / `errorMessage`.
  Any code that can hold state can drive them.
- **Consistent form UX** — one label, error and helper-text system across all fields,
  including `showLabelAboveFormField` and hidden-label modes with accessible names preserved.
- **Accessibility built in** — generated `id`s plus `aria-label`, `aria-labelledby`,
  `aria-describedby`, `aria-invalid` and `aria-required` wired on every field.
- **Thin on top of MUI** — nearly all underlying Material UI props pass straight through
  (`variant`, `slotProps`, `sx`, etc.), so nothing about MUI is hidden from you.
- **Typed and tree-shakable** — strict TypeScript generics for option-based fields and
  per-component subpath imports.

## Versions & roadmap

This library is a port of `@nish1896/rhf-mui-components` **v4** and supports
MUI `v6` and `v7`. Development for MUI `v9` and the matching MUI X Date
Pickers release is already underway, but it will take some time to ship for
both packages, as both projects are maintained by a single developer.

## Theming & defaults

Wrap your app in the `ConfigProvider` to set package-wide defaults — label
placement, default `sx` for labels and helper text, and the date adapter used
by the pickers:

```tsx
import { ConfigProvider } from '@nish1896/mui-components/config';
import { AdapterDayjs } from '@mui/x-date-pickers/AdapterDayjs';

<ConfigProvider allLabelsAboveFields dateAdapter={AdapterDayjs}>
  <App />
</ConfigProvider>
```

See [Customization](/customization) for a working example.
