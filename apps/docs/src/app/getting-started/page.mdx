# Getting Started

Owing to the strong utility of `@nish1896/rhf-mui-components`, the need to make
a standalone package for material-ui components, which could be used either
individually or for any form library was quite evident. This would save developers,
both junior and senior a significant amount of time and effort to get develop
form UI in the best possible way.
 
Coming from `@nish1896/rhf-mui-components`? The component surface is the same —
`control` and `registerOptions` are replaced by the controlled `value` /
`onValueChange` / `errorMessage` contract shown above.

## Versions & roadmap

Currently this library has been ported over from the **version-4** of
`@nish1896/rhf-mui-components`, which supports MUI `v6` and `v7`. The
development to support `v9` of MUI and X-Date Pickers has already started,
but will take some time to release for both the packages, since both projects
right now are managed by a single developer.

| Package | Status | Compatibility |
| ------- | ------ | ------------- |
| `@nish1896/mui-components` **v1** | current | MUI v6 / v7, React 18+ |
| `@nish1896/mui-components` **v2** | planned | MUI v9 |
| `@nish1896/rhf-mui-components` **v4** | maintained | MUI v6 / v7, React 18+ |
| `@nish1896/rhf-mui-components` **v5** | planned | MUI v9 |

## Installation

```bash
pnpm add @nish1896/mui-components
```

The package expects Material UI (v6 or v7) and its peers in your app:

```bash
pnpm add @mui/material @mui/icons-material @emotion/react @emotion/styled
```

Date & time pickers additionally use [MUI X](https://mui.com/x/react-date-pickers/)
(v7 or v8) and a date adapter of your choice:

```bash
pnpm add @mui/x-date-pickers dayjs
```

## Quick start

Import components from their subpath and control them like any other input:

```tsx
import { useState } from 'react';
import MUITextField from '@nish1896/mui-components/mui/textfield';

export default function SignupName() {
  const [firstName, setFirstName] = useState('');
  const [error, setError] = useState();

  return (
    <MUITextField
      fieldName="firstName"
      value={firstName}
      onValueChange={({ newValue }) => setFirstName(newValue)}
      onBlur={() => setError(firstName ? undefined : 'First name is required')}
      errorMessage={error}
      required
    />
  );
}
```

There is no schema, resolver or registration step — derive `errorMessage` from your
own validation (or your form library's) and the field renders in an error state.

## Bring your own form library

Because the components are controlled, adapting them to a form library is a few
lines. With React Hook Form's `Controller`:

```tsx
import { Controller, useForm } from 'react-hook-form';
import MUITextField from '@nish1896/mui-components/mui/textfield';

const { control } = useForm();

<Controller
  name="email"
  control={control}
  rules={{ required: 'Email is required' }}
  render={({ field, fieldState }) => (
    <MUITextField
      fieldName="email"
      value={field.value}
      onValueChange={({ newValue }) => field.onChange(newValue)}
      onBlur={field.onBlur}
      errorMessage={fieldState.error?.message}
    />
  )}
/>
```
