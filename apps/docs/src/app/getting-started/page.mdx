# Getting Started

`@nish1896/mui-components` grew out of
[`@nish1896/rhf-mui-components`](https://rhf-mui-components.vercel.app/): its
components proved useful enough that a standalone Material UI package — usable
on its own or with any form library — was the natural next step. It saves
developers, junior and senior alike, significant time and effort in building
consistent form UIs.

<Callout type="info">
  Coming from `@nish1896/rhf-mui-components`? The component surface is the
  same — `control` and `registerOptions` are replaced by the controlled
  `value` / `onValueChange` / `errorMessage` contract shown below.
</Callout>

## Installation

Install the package:

```bash
pnpm add @nish1896/mui-components
```

The package expects Material UI (`v6` or `v7`) and its peers in your app.
Match your project's MUI version by installing with the `latest-v6` or
`latest-v7` tag:

```bash
pnpm add @mui/material@latest-v7 @mui/icons-material@latest-v7 @emotion/react @emotion/styled
```

Date & time pickers additionally use [MUI X](https://mui.com/x/react-date-pickers/)
(`v7` or `v8`) and a date adapter of your choice, with `AdapterDayjs` being
[recommended by Material UI](https://v8.mui.com/x/react-date-pickers/base-concepts/#recommended-library).

```bash
pnpm add @mui/x-date-pickers dayjs
```

To minimize the bundle size during the build process, this package includes both
named and default exports within each module. Similar to Material-UI, developers 
are encouraged to use default import syntax to [reduce bundle size](https://v7.mui.com/material-ui/guides/minimizing-bundle-size/).

The type for each component can also be imported to modify or customize an 
existing component.

## Quick start

Import components from their subpath and control them like any other input:

```tsx
import { useState } from 'react';
import MUITextField from '@nish1896/mui-components/mui/textfield';

export default function SignupName() {
  const [firstName, setFirstName] = useState('');
  const [error, setError] = useState<string>();

  return (
    <MUITextField
      fieldName="firstName"
      value={firstName}
      onValueChange={({ newValue }) => setFirstName(newValue)}
      onBlur={() => setError(firstName ? undefined : 'First name is required')}
      errorMessage={error}
      required
    />
  );
}
```

There is no schema, resolver or registration step — derive `errorMessage` from
your own validation (or your form library's) and the field renders in an error
state.

## Bring your own form library

Because the components are controlled, adapting them to a form library takes
only a few lines. With React Hook Form's `Controller`:

```tsx
import { Controller, useForm } from 'react-hook-form';
import MUITextField from '@nish1896/mui-components/mui/textfield';

const { control } = useForm();

<Controller
  name="email"
  control={control}
  rules={{ required: 'Email is required' }}
  render={({ field, fieldState }) => (
    <MUITextField
      fieldName="email"
      value={field.value}
      onValueChange={({ newValue }) => field.onChange(newValue)}
      onBlur={field.onBlur}
      errorMessage={fieldState.error?.message}
    />
  )}
/>
```

## Theming & defaults

Wrap your app in the `ConfigProvider` to set package-wide defaults — label
placement, default `sx` for labels and helper text, and the date adapter used
by the pickers:

```tsx
import { ConfigProvider } from '@nish1896/mui-components/config';
import { AdapterDayjs } from '@mui/x-date-pickers/AdapterDayjs';

<ConfigProvider allLabelsAboveFields dateAdapter={AdapterDayjs}>
  <App />
</ConfigProvider>
```

See [Customization](/customization) for a working example.
