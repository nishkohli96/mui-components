# MUIAutocomplete

`MUIAutocomplete` wraps the Material UI [Autocomplete](https://v7.mui.com/material-ui/react-autocomplete/)
and stores **primitive** values (the option string, or the `valueKey` property
for object options). It supports single or multiple selection, `disableClearable`
and `freeSolo`.

Use [MUIAutocompleteObject](autocomplete-object) when you need to store the full option object.

## Usage

```tsx
import MUIAutocomplete, {
  MUIAutocompleteProps
} from '@nish1896/mui-components/mui/autocomplete';
```

```tsx
const [color, setColor] = useState<string | null>(null);

<MUIAutocomplete
  fieldName="color"
  options={['Red', 'Green', 'Blue']}
  value={color}
  onValueChange={({ newValue }) => setColor(newValue)}
/>
```

A single select stores a `string`, or `null` when nothing is selected, and
`multiple` stores a `string[]`. `undefined`, `null` and `[]` all mean no
selection. A value that doesn't match any option isn't displayed, unless
`freeSolo` is on.

`onValueChange` receives `{ newValue, selectedOption, event, reason, details }`.
`newValue` is the normalized value to store, and `selectedOption` is the raw
Material UI selection: the option object, or the typed string with `freeSolo`.
`event`, `reason` (such as `selectOption`, `removeOption`, `clear` or
`createOption`) and `details` come straight from the Material UI change handler.

### With an array of objects

Options can also be objects. In this case, both `labelKey` and `valueKey`
**are required**. `labelKey` is the property used as each option's visible
label, and `valueKey` is the property used as its value. `value` then holds
the `valueKey` property of the selected option, not the whole object.

To store the whole object, use [MUIAutocompleteObject](autocomplete-object) instead.

```jsx
<MUIAutocomplete
  fieldName="countriesVisited"
  options={countryList} // imported from MUICountrySelect
  labelKey="name"
  valueKey="iso3"
/>
```

### Multiple selection

Set `multiple` to store a `string[]` and show each selection as a chip.
The menu stays open while the user picks, whereas a single select closes
and blurs after a choice.

While the field is not focused, only the first `limitTags` chips (default `2`)
are shown, followed by a "**+N More**" chip. `limitTags={-1}` shows all of
them, and `getLimitTagsText` receives the number of hidden chips and returns
your own text. `ChipProps` customizes the chips.

```tsx
const [skills, setSkills] = useState<string[]>([]);

<MUIAutocomplete
  fieldName="skills"
  options={['React', 'Vue', 'Angular', 'Svelte', 'Solid']}
  value={skills}
  onValueChange={({ newValue }) => setSkills(newValue)}
  multiple
  limitTags={3}
  getLimitTagsText={hiddenCount => `+${hiddenCount} skills`}
  ChipProps={{ color: 'primary', size: 'small' }}
/>
```

### Free text entry

`freeSolo` lets the user enter a value that isn't in `options`. The typed string is passed to
`onValueChange` as it is and stored in `value`. `autoSelect` defaults to `true` with `freeSolo`, so text
typed in the field is committed when it loses focus. Pass `autoSelect={false}` to require Enter.
With `multiple`, each typed value becomes its own chip.

```tsx
const [city, setCity] = useState<string | null>(null);

<MUIAutocomplete
  fieldName="city"
  options={['Delhi', 'Mumbai', 'Pune']}
  value={city}
  onValueChange={({ newValue }) => setCity(newValue)}
  freeSolo
/>
```

<Callout type="note">
When using `freeSolo` with object-based options, custom renderers such as `renderValue`, `renderTags`,
or `renderOption` should account for both option objects and user-entered string values. A common
approach is:

```ts
typeof value === 'string'
```
to distinguish free-form input from predefined option objects.
</Callout>

### Clearing the value

A clear button is shown once there is a value. `disableClearable` removes it, so `newValue` is never
`null` and the value type no longer includes `null`. Give the field an initial value in that case.

```tsx
const [color, setColor] = useState('Red');

<MUIAutocomplete
  fieldName="color"
  options={['Red', 'Green', 'Blue']}
  value={color}
  onValueChange={({ newValue }) => setColor(newValue)}
  disableClearable
/>
```

### Loading state

Set `loading` while the options are being fetched. A small spinner appears at the end of the input,
and when there are no options yet, the popup shows the loading text (`loadingText`, `Loading…` by
default) instead of "No options".

`circularProgressProps` customizes the spinner, which is `20px` by default.

```tsx
<MUIAutocomplete
  fieldName="user"
  options={users}
  value={user}
  onValueChange={({ newValue }) => setUser(newValue)}
  loading={isFetchingUsers}
  circularProgressProps={{ size: 16 }}
/>
```

### Customizing the input

`textFieldProps` is forwarded to the underlying `TextField`, for example a `placeholder`, `variant` or
`size`. `autoHighlight` is `true` by default, which differs from Material UI, so the first option is
highlighted as the user types and Enter selects it. Pass `autoHighlight={false}` to turn that off.
A `ref` gives you the input element.

```tsx
const inputRef = useRef<HTMLInputElement>(null);

<MUIAutocomplete
  fieldName="color"
  options={['Red', 'Green', 'Blue']}
  value={color}
  onValueChange={({ newValue }) => setColor(newValue)}
  ref={inputRef}
  autoHighlight={false}
  textFieldProps={{ placeholder: 'Pick a colour', size: 'small' }}
/>
```
